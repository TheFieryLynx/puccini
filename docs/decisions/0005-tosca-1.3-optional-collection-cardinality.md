# TOSCA 1.3 optional collection cardinality

## Status

Accepted for strict TOSCA 1.3 structural validation.

## Normative source

TOSCA Simple Profile in YAML Version 1.3:

- §3.6.20.1, “Keynames”
- §3.6.20.2.2, “Extended notation for use in Template definitions”
- §3.7.5.1, “Keynames”
- §3.7.5.2, “Grammar”
- §3.8.5.1, “Keynames”
- §3.8.5.2, “Grammar”

## Ambiguity

The keyname tables mark interface `operations`, interface `notifications`, and
group `members` as optional. Their grammar descriptions call the represented
collection a required map or list of one or more entries.

Requiring the keynames themselves would contradict the explicit “Required: no”
table entries. Allowing an explicitly present empty collection would discard
the “one or more” grammar cardinality.

## Decision

The keynames may be omitted. When one of these keynames is explicitly present,
its map or list must contain at least one entry.

This is an interpretation of the combined normative text, not a claim that the
specification explicitly states the conditional rule in one sentence.

## Consequences

- Omitted optional collections remain valid.
- Explicit empty `operations`, `notifications`, or `members` collections are
  rejected during structural reading.
- TOSCA 2.0 readers do not receive this TOSCA 1.3-specific cardinality rule.
- The frozen TOSCA 1.3 catalog and denominator remain unchanged.
