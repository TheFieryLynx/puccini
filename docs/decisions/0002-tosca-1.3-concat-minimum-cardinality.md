# TOSCA 1.3 concat minimum cardinality

## Status

Accepted for strict TOSCA 1.3 processing.

## Context

TOSCA Simple Profile in YAML 1.3 contains contradictory cardinality language
for `concat`:

- Section 4.3.1, “concat”, says the function concatenates “two or more”
  string values.
- Section 4.3.1.1, “Grammar”, uses
  `concat: [<string_value_expressions_*>]`.
- Section 4.3.1.2, “Parameters”, defines the parameter as a list of “one or
  more” strings or string-valued expressions and marks it required.

The generated atomic MUST record `TOSCA13-4.3.1.2-003` captures the required
parameter. The frozen catalog and denominator are not changed by this
decision.

## Decision

Strict TOSCA 1.3 processing accepts one or more `concat` arguments and rejects
an empty argument sequence. The parameter table is treated as the more
specific grammar contract because it defines the parameter's requiredness,
type, and minimum cardinality together.

This is an implementation interpretation of contradictory specification
language, not a claim that section 4.3.1 explicitly permits a one-argument
call.

## Consequences

- `{ concat: [value] }` is accepted.
- `{ concat: [] }` is rejected in the read phase.
- Direct boundary tests lock both outcomes.
- A future catalog-review task may cross-reference this decision, but must not
  change the frozen 223 denominator as part of an implementation task.
