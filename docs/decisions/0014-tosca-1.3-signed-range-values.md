# TOSCA 1.3 signed numeric range values

The pinned TOSCA 1.3 specification, sections 3.3.3.1 (Grammar) and 3.3.3.2
(Keywords), defines two integer bounds, upper greater than or equal to lower,
and the UNBOUNDED upper keyword. It does not restrict generic numeric ranges to
non-negative integers. Occurrence/cardinality values retain their separate
non-negative domain. PortSpec retains the existing [1,65535] domain from
section 5.3.11.2. The table in 5.3.11.1 instead says 65536; that historical
profile ambiguity is not adjudicated by this signed-range remediation.

Use a TOSCA 1.3 native range with signed 64-bit integer endpoints. Its upper
pointer is nil for UNBOUNDED, serialized as null; this preserves the distinction
between the largest finite supported integer and no finite upper bound. The
normalized lower/upper object is a Puccini representation choice, not a TOSCA
source grammar. Existing positive scalar tests keep their numerical assertions
and now inspect the version-specific native value. Range-valued `in_range`
constraints use the same signed endpoint comparison.

The shared unsigned range reader remains available for cardinalities and the
existing TOSCA 2.0 grammar. No 2.0 reader or native range semantics change in this
commit. The full regression suites verify version isolation.
