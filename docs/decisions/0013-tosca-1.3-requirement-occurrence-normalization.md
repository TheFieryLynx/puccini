# TOSCA 1.3 requirement occurrence intervals

Sections 3.7.3.1 (Keynames) and 3.8.2.1–3.8.2.2.2 (Requirement assignment)
require a lower and upper occurrence bound, inheritance of an omitted assignment
range, and containment of an explicit assignment range in the effective
requirement definition range. The containment sentence appears immediately
before the malformed 3.8.2.3 Examples heading in the pinned HTML.

Puccini represents a TOSCA 1.3 requirement declaration as a normalized requirement
with `occurrences.lower` and `occurrences.upper`. A null upper bound denotes
UNBOUNDED. A zero lower bound retains the declaration; it does not delete its
possible dependencies. Multiple explicit source declarations remain separate.
Generated unit placeholders for one absent declaration are represented together
by the effective interval. This is a normalization representation choice, not
specification-defined output grammar or an instruction to instantiate resources.
Consumers of normalized TOSCA 1.3 graphs must interpret this interval.

The earlier representation expanded the lower bound as an exact count and lost
the upper bound. TOSCA 2.0 section 8.5 instead defines an exact assignment count;
its existing expansion and serialized representation are retained. A grammar
callback isolates the 1.3 normalization policy. Invalid explicit intervals fail
after inheritance, before rendering or normalization. The frozen MUST catalog
is unchanged; the omitted containment obligation remains a catalog proposal.
