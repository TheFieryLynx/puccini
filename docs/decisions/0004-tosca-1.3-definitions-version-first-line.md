# TOSCA 1.3 definitions version first-line rule

## Status

Accepted for strict TOSCA 1.3 processing.

## Context

TOSCA Simple Profile in YAML 1.3 contains different normative strengths for
the placement of `tosca_definitions_version`:

- Section 3.1.2, “TOSCA Namespacing in TOSCA Service Templates”, states that
  every TOSCA service template MUST have `tosca_definitions_version` as the
  first line.
- Section 3.10.2.1, “Keynames”, later states that
  `tosca_definitions_version` SHOULD be the first line.

The frozen atomic requirement `TOSCA13-3.1.2-001` records the section 3.1.2
MUST. The catalog and denominator are not changed by this decision.

## Decision

Strict TOSCA 1.3 processing enforces the section 3.1.2 MUST and rejects a
template when another YAML mapping key precedes the definitions-version key.
Comments, directives, and blank lines do not define service-template keynames
and therefore do not violate the rule. The check uses source location metadata
and runs in the structural read phase.

This is an implementation interpretation of contradictory normative language,
not a claim that section 3.10.2.1 uses MUST.

## Consequences

- A TOSCA 1.3 service template with a preceding YAML key is rejected.
- The selected grammar is still determined from the definitions-version
  value; the additional diagnostic identifies the placement violation.
- TOSCA 2.0 behavior is unchanged.
- The frozen denominator remains 223.
